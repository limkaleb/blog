Notes from reading **"Yes, and..."** by Carson Gross (the htmx guy), published Feb 27, 2026. Source: [htmx.org/essays/yes-and](https://htmx.org/essays/yes-and/). Go read the original, this is just my short version so I don't forget it.

He answers the question "should I still become a programmer given AI?" with **"Yes, and..."**

## The "Yes"
- Programming is really about solving problems with computers and keeping the complexity under control. That skill isn't going away.
- You still have to write the code yourself, especially as a junior. If you've never written it, you can't judge whether the AI's code is any good, and you won't build architectural intuition.
- Going from assembly to high-level languages isn't the same as going from code to prompts. LLM output isn't deterministic and often adds complexity nobody needed.
- AI is fine as a "TA" for learning, as long as it doesn't do the work for you.

## The "and..."
Raw coding will matter a bit less. These matter more:
- Communication
- Understanding the business
- Software architecture
- Knowing how to use LLMs well

## How he uses LLMs
This was the part I cared about most. He typically uses them to:
- Analyze existing code, to understand it and spot issues or inconsistencies
- Organize his thoughts before a bigger project
- Generate small pieces of code for a system he's working on
- Write code he doesn't enjoy writing, like regex and CSS
- Make throwaway demos or exploratory code he won't maintain
- Suggest tests for a feature

And what he avoids:
- Having an LLM generate a full solution that he'll have to maintain
- Letting it design the APIs of his systems

He also sometimes uses it next to his own manual coding, to learn APIs and see what options exist.

## Jobs
The market is bad right now, but he thinks it's cyclical. His advice is to use your network (family, friends, and friends of family) instead of online job boards. Non-tech companies need programmers too.

## My takeaway
Use LLMs for the boring stuff and for exploring, but keep writing the code I actually have to own.
